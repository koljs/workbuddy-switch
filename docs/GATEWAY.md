# OpenAI 兼容网关、风控体检与出口治理

本仓库在原有「账号切换 / 会话 / 积分 / Token 统计」之外，新增四块能力：

1. **OpenAI 兼容网关**：把账号库变成一个标准 OpenAI 接口，任何支持自定义端点的客户端
   （Cherry Studio、ChatBox、Cline、Continue、Dify、各类 OpenAI SDK）填上地址与密钥即可直接用。
2. **风控体检**：给每个账号真发一条最小对话，判断这个号现在还能不能用，并把结论写回账号库，
   供网关挑号时参考。
3. **出口 IP 检测与换 IP 向导**：显示当前公网出口 IP 与归属地，并统计这个出口上已经挂了
   多少个号——这才是要不要换 IP 的判断依据。
4. **账号级 HTTP 代理**：给单个账号指定出口代理，让不同号走不同 IP。

四块能力都实现在 `wb-switch-core` 里，桌面端（Tauri commands）与 webui（HTTP server）共用
同一份实现，两边行为一致。

## 为什么需要网关

号多了以后，官方客户端一次只能登一个号。网关把整个账号库变成一个端点：

- 请求按「最久没用过的号优先」自动换号，客户端侧无感
- 某个号撞限额、token 失效或上游偶发拒绝时，自动切下一个号重试
- 积分最紧的号也能被利用起来，不必手工切号
- 统一的每日上限与用量统计，避免某个客户端把额度刷爆

## 两套独立网关

国内版与国际版是**两套完全独立的网关**，这是刻意的设计：

| | 国内版 | 国际版 |
| --- | --- | --- |
| 接口路径 | `/v1` | `/v1-global` |
| 密钥 | 各自一把，不通用 | 各自一把，不通用 |
| 参与的号 | 只走国内版账号 | 只走国际版账号 |
| 每日上限 / 用量 | 各算各的 | 各算各的 |
| 可用模型 | 各查各的 | 各查各的 |

填了哪个地址就一定在打哪一边的号，不会串。密钥填错版本会直接 401。

## 快速开始

1. 账号页先保存至少一个账号
2. 侧栏进入「OpenAI 网关」，把要用的一侧打开「启用」
3. 复制该侧的 **接口地址** 与 **密钥**
4. 在客户端里填：
   - Base URL：`http://127.0.0.1:57890/v1`（桌面端与 webui 的端口以实际监听为准）
   - API Key：卡片上复制的那一串，一字不差
5. 点「查可用模型」确认这一侧当前能用哪些模型

## 号池与换号重试

- **候选号**：该档位的全部账号，或「参与轮转的号」里勾选的那批
- **剔除**：刚被体检判为风控（6 小时内）的号不参与轮转；若全部被剔除则退回全集
  （宁可拿它试一把，也不直接报「没有可用账号」）
- **排序**：最久没用过的优先 → 正在服务其它请求的排后 → 冷却中的垫底
- **重试**：单次请求最多尝试 `MAX_ACCOUNT_TRIES`（4）个账号
- **冷却**：某个号失败后进入 90 秒冷却；成功即清除冷却

## 风控体检

上游风控是**按账号**下手的：被风控的号 token 照样能续期、积分照样能查，但一发对话就被拒
（上游 `code 11140`）。所以只有真发一条对话才知道还能不能用——换 IP、换 token 都无效，
限制挂在号本身。

四种结论，处置方式完全不同：

| 结论 | 含义 | 处置 |
| --- | --- | --- |
| ✅ 可用 | 对话链路正常 | 什么都不用做 |
| 🚫 风控拦截 | 上游 `11140` | 只能等官方解除，或在官方客户端内点「反馈」申诉 |
| 🔑 登录态失效 | token 坏了 | 重新登录这个号 |
| ⚠️ 网络问题 | 请求没发出去 / 没收到响应 | 排查本机网络，不一定是号坏了 |
| ⚠️ 其他 | 凭证文件缺失等 | 按提示那行文字排查 |

体检**只读不改号**：不把号打进冷却、不算进网关用量。唯一的写入是把结论记进账号记录的
`risk_state` / `risk_at`，供网关挑号时参考。

## 出口 IP 与账号级代理

体检回答的是「这个号现在能不能用」，出口治理回答的是「怎么别让号变成不能用」。上游风控
除了看号本身，也看**同一个出口 IP 上短时间出现了多少个账号**。这一组能力就是围绕这一点：

**出口 IP 检测**（账号页顶部）

- 显示当前公网出口 IP、归属地、运营商，5 分钟内走缓存（避免每次开页都打探测接口）
- 统计这个 IP 上挂了哪些号；达到 `SHARING_WARN_THRESHOLD`（2）就在顶部给出警示
- 探测源按顺序尝试：`ip-api`（带中文归属地）→ `ipify` → `ipapi.co`，任一成功即止

归属来自账号上的 `egress_ip` 字段（保存/分配时写入），**不是**用「当前 IP 反推」——号可能
是几天前在别的网络下登录的，反推出来的归属是错的。

**换 IP 向导**（顶部「换 IP 向导」按钮）

四步，每步都给出「怎么算做完了」，避免凭感觉判断：

1. 记录当前出口 IP（建立基线）
2. 切换网络出口（飞行模式 / 宽带重拨 / 换热点 / 换代理）
3. **重新检测确认 IP 真的变了**——这一步必须走 `force` 绕过缓存，否则读到的是换之前的
   缓存值，会把「没换成功」显示成成功
4. 用新 IP 登录新号，并把当前 IP 写进这些号的记录

**账号级代理**（账号卡片菜单 →「出口代理」）

- 每个号单独配 `http://host:port`（可带 `user:pass@`），留空 = 直连
- 只支持 `http://` / `https://`：`reqwest` 在本项目里没开 `socks` feature，`socks5://`
  会在归一化阶段就被明确拒绝，而不是留到发请求时报一个含混的底层错误
- 保存前可跑「测试连通性」：经该代理访问一个轻量公网接口，返回往返毫秒与该代理看到的
  出口 IP。代理地址写错、代理没启动、需要认证这三种失败分开报，因为处置方式不同
- 配好之后，该账号的**对话、token 续期、风控体检**都走这个出口——只在对话时走代理而续期
  直连，等于把号的位置暴露在同一台机器上

代理地址统一在写入前过 `proxy::normalize`，落库的一定是能直接喂给 reqwest 的形态。返回给
界面的地址是 `proxy::mask` 掩码后的（密码替换成 `***`）。

## 上游协议

出站请求头是**风控指纹**，缺了会被上游 `403 code 10085`，因此逐个显式声明在
`crates/wb-switch-core/src/modules/gateway.rs` 里，不做「看起来更简洁」的合并：

- UA：`WorkBuddy/<桌面版本> <品牌>/<桌面版本> CLI/<CLI 版本>`
  （国际版第二段品牌是 `WorkBuddy AI`，送错会 403）
- `X-Machine-ID` / `X-Session-ID`：按 `uid + 用途` 稳定派生（同一账号每次相同，绝不能用随机值）
- 对话专属：`X-Domain: chat`、`X-Product: SaaS`、`X-IDE-Name: WorkBuddy`、`X-IDE-Version`
- 端点：国内版 `https://copilot.tencent.com/v2/chat/completions`；
  国际版先试 `/console/chat/completions`，404/405 再回落 `/v2/chat/completions`

## 文件与配置

| 文件 | 内容 |
| --- | --- |
| `~/.wb-switch/gateway.json` | 两个档位的启用状态、密钥、每日上限、号池 |
| `~/.wb-switch/gateway-usage.json` | 两个档位的用量（今日 / 累计 / tokens / 失败数） |
| `~/.wb-switch/egress.json` | 当前出口 IP（含归属地）+ 最近 50 条历史出口 IP |
| 账号库 `accounts.json` | 体检结论写进各账号的 `risk_state` / `risk_at`；出口记录写进 `egress_ip` / `egress_at`；代理写进 `proxy` |

## 已知限制

- **流式不是逐帧透传**：当前实现会先把上游流读完，再按 OpenAI SSE 格式输出。
  协议完全正确，但首字延迟等于整段生成时间。要做到逐帧透传，需要在 core 里
  给 reqwest 打开 `stream` feature 并改成 `bytes_stream()` 消费。
- **模型目录有 10 分钟缓存**：上游模型变动很慢，缓存避免每次开页都打上游。
- **`/v1` 系列只绑定本机**：webui 与桌面端都只监听 `127.0.0.1`，不要直接暴露到公网；
  需要异地访问请自行加一层反向代理并做好鉴权。
